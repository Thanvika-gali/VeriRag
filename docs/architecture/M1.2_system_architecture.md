## 2. Component Specifications

### 2.1 Evaluation Input Module
- **Inputs:** Question (Required), AI Generated Response (Required), Reference Answer (Optional), Source Document (Optional TXT/PDF or text string).
- **Validation:** Pydantic models enforcing string non-emptiness, numerical range limits on `top_k`, and MIME/extension checks on file uploads.

### 2.2 Backend & API Layer
- **Framework:** FastAPI with Uvicorn server.
- **Endpoints:**
  - `POST /api/submissions`: Primary endpoint validating inputs, retrieving relevant evidence, and saving records.
  - `GET /api/submissions`: Retrieves historical submissions with evidence count.
  - `GET /api/submissions/{id}`: Returns submission details with full evidence payloads.
  - `POST /api/upload-document`: Processes multi-part TXT/PDF uploads using `DocumentParser`.
  - `GET /api/health`: Monitors database connection, embedding model status, and indexed vector counts.

### 2.3 Evaluation Submission Database
- **Engine:** SQLite (`submissions.db`).
- **Schema:**
  - `id`: Unique UUIDv4 string (Primary Key).
  - `question`: Query text.
  - `ai_response`: Model response text.
  - `reference_answer`: Ground truth answer string (nullable).
  - `source_document`: Source document text (nullable).
  - `status`: Lifecycle state (`completed`, `failed`).
  - `retrieved_evidence_json`: JSON-serialized array of evidence items.
  - `created_at`: ISO 8601 UTC timestamp.

### 2.4 Reference Knowledge Base & Ingestion Pipeline
- **TruthfulQA Ingester:** Ingests `truthfulqa/truthful_qa` (`generation` config), extracting question, best truthful answer, and verified factual facts into unified reference passages.
- **SQuAD Ingester:** Ingests `rajpurkar/squad`, extracting topic title, Wikipedia context passages, and reference Q&A pairs.
- **Standardized Schema:** Preserves dataset origin (`TruthfulQA` vs `SQuAD`), question IDs, categories, titles, and sources in structured chunk metadata.

### 2.5 Cleaning, Chunking & Embedding Pipeline
- **Cleaner (`TextCleaner`):** Unicode NFKC normalization, removal of unprintable control characters, and whitespace normalization.
- **Chunker (`DocumentChunker`):** Recursive character text splitter parameterized by `chunk_size=500` and `chunk_overlap=50`. Preserves parent document ID, chunk index, total chunks, and character counts.
- **Embedding Generator (`EmbeddingGenerator`):** Dense vector generation using `sentence-transformers/all-MiniLM-L6-v2` producing normalized 384-dimensional vectors.

### 2.6 Vector Database & Semantic Retrieval
- **Vector Database:** `ChromaDB` (persistent local storage in `chromadb_data/`).
- **Index:** HNSW indexing using Cosine distance metric.
- **Retriever (`EvidenceRetriever`):** Encodes query string, searches the collection for top-$K$ nearest neighbors, and translates distance into bounded similarity scores $\text{score} \in [0.0, 1.0]$.

### 2.7 Future AI Evaluation Agent Layer (M2 Specification)
The evaluation agent interfaces are located in `evaluation/agents/`:
1. **Relevance Judge Agent (`RelevanceJudgeAgent`):** Evaluates if the response addresses the core question intent.
2. **Accuracy Judge Agent (`AccuracyJudgeAgent`):** Verifies response claims against retrieved evidence.
3. **Hallucination Detection Agent (`HallucinationDetectionAgent`):** Flags unsupported or fabricated assertions.
4. **Completeness Judge Agent (`CompletenessJudgeAgent`):** Verifies question aspect coverage.
5. **Verdict Agent (`VerdictAgent`):** Aggregates dimension scores into an overall verdict.

## 3. Data Flow Execution Sequence (M1)

```
[Client (UI / REST)] 
    ──(1) Submit Question + AI Response (+ Doc)──> [FastAPI Backend]
                                                            │
                                                  (2) Parse & Validate
                                                            │
                                                            ▼
                                                [EvidenceRetriever]
                                                            │
                                                (3) Generate 384-d Query Vector
                                                            │
                                                            ▼
                                                [ChromaDB Vector Store]
                                                            │
                                                (4) Cosine Nearest-Neighbor Search
                                                            │
                                                            ▼
                                                [Top-K Ranked Evidence Chunks]
                                                            │
                                                (5) Persist to SQLite (submissions.db)
                                                            │
    <──(6) Return JSON Response with Evidence Details────────
```
